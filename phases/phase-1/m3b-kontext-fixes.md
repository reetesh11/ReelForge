# ReelForge Phase 1 / M3b — Kontext default and live-run fixes

Binding inputs: `ReelForge — Technical Spec.md` (Draw Things adapter, spike S1 finding, `models.toml`), `phases/phase-1/m3-cast.md` (R1, R8). Follow-up to M3 (PR #3, merged), found by a live run on the reference Mac with Draw Things and the Kontext model. Requires `m3-cast` merged. The M3 acceptance tests are frozen history; where one pins the old default (Schnell, permissive licence, 4 steps) this task revises it deliberately at Gate 2.

## Requirements
- R1. Doctor model probe: `DrawThingsAdapter` health check must ask Draw Things for the smallest image it accepts (128 x 128, 1 step). The previous 64 x 64 probe is rejected by the real server with HTTP 422 for any model, so doctor always reported the pinned model as missing. Keep: 422 on an unknown model still fails doctor with "Draw Things doesn't have the model <id>" and a timeout counts as fine. (A fix exists as commit `097e493` on the old `congoforce/m3-cast` branch: size 128, one unit test; reuse it.)
- R2. Per-model sampling steps: `models.toml` gets an optional `steps` field per model entry. The Draw Things adapter uses it when the task gives no `steps` (precedence: task param, then model entry, then a built-in default of 4). Rationale: the built-in default 4 suits FLUX.1 Schnell; with Kontext at 4 steps images come out badly blurred, at 20 steps they are sharp (verified live, same prompt and seed). The cast job (generate and refine) must use the model's steps.
- R3. Default image model: `models.toml` `[models.image]` becomes `flux_1_kontext_dev_q8p.ckpt` (the checkpoint name Draw Things reports), `steps = 20`, license `FLUX.1 Kontext [dev] Non-Commercial License`, license_url `https://huggingface.co/black-forest-labs/FLUX.1-Kontext-dev`. With this default the non-commercial licence warning shows in `/health`, the Status panel and the Cast screen, and approval asks for confirmation ("Approve anyway").
- R4. Tests that pin the old default are revised, not worked around: the tests asserting the default model has a permissive licence and no warning (`test_permissive_licence_has_no_warning_in_cast`, `test_health_has_no_licence_key_for_permissive_default_model`) should instead set a permissive model explicitly through a temporary `models.toml` and keep asserting the "no warning" behaviour. The Playwright flow in `web/e2e/cast.spec.ts` clicks "Approve anyway".
- R5. `docs/manual-checks.md` M3 step 2 and 11 reflect the default (amber licence row and confirmation dialog are expected), and step 4 notes the expected time per image (about 1 minute at 20 steps) and that images must be sharp.

## Acceptance criteria
- AC-1: Against a stub that returns 422 for width or height below 128 (like the real server), the doctor model check passes for a known model and fails with the "doesn't have the model" message when the stub rejects the model name.
- AC-2: A `steps` value in a `models.toml` entry is sent as `steps` in the txt2img and img2img requests when the task gives none; a task-level `steps` overrides it; with neither, the request carries 4.
- AC-3: With the packaged `models.toml`, the cast job's Draw Things requests carry `model` `flux_1_kontext_dev_q8p.ckpt` and `steps` 20 (stub server, no GPU).
- AC-4: With the packaged `models.toml`, `/health` has `image_licence_warning` naming the Kontext non-commercial licence, the Cast screen shows it, approval still succeeds after confirming, and each artifact's sidecar records the licence.
- AC-5: With an explicit permissive model entry, none of the licence warnings appear (the behaviour M3 AC-7 requires).
- AC-6: Ruff, pyright, eslint, `tsc --noEmit`, the web build, the full test suite and the Playwright flow pass.
- AC-7: Manual check on the reference Mac (human visual check): with Draw Things running and Kontext loaded, `reelforge doctor` shows `draw_things` passing, and one `cast.generate` job renders 4 sharp 9:16 candidates in about 1 minute each.
