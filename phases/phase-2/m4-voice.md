# ReelForge Phase 2 / M4 — Voice

Binding inputs: `ReelForge — Requirements Document.md`, `ReelForge — Product Spec.md` (Stage 3 Voice-overs, Cast library, States, Manual edit options for Voice), `ReelForge — Technical Spec.md` (milestone M4, mlx-audio adapter and `tts_worker.py`, task `gen_voice_take`, Shot length and frame math, spike S3 finding). The Technical Spec wins on design; the Requirements Document wins on acceptance. Parent: `phases/phase-2-voice-frames-shots.md`. Requires Phase 1 merged (M1 to M3c). Out of scope here: key frames and shots (M5).

## Spike inputs (already decided, do not re-research)
- Spike S3 (Technical Spec, Nov 3, 2026): default voice model **OmniVoice** (`mlx-community/OmniVoice-bfloat16`, Apache-2.0), fallback **Kokoro** (`mlx-community/Kokoro-82M-bf16`, Apache-2.0). Voxtral is CC-BY-NC (do not make it a default) and Qwen3-TTS has no Hindi. Language scope for v1: **Hindi only** in the voice UI and defaults.
- mlx-audio 0.6.4 runs in its own arm64 uv project at `~/tools/mlx-audio-env` (setting `[tools.mlx_audio] project_path`). Extra packages that environment needs: `misaki`, `espeakng-loader`, `phonemizer-fork`, `num2words`, `spacy` (Kokoro Hindi) and `mistral-common[audio]` (Voxtral only). Pin an arm64 Python (`uv venv --python cpython-3.12-macos-aarch64-none`); uv can otherwise pick an x86_64 Python and fail to find MLX wheels.
- Model call shapes (mlx-audio `load_model(id).generate(text=…)` yields results with `.audio` and `.sample_rate`; 24 kHz): OmniVoice takes `language="hi"` and, for cloning, `ref_audio` and `ref_text`; Kokoro takes `voice` (`hf_alpha`, `hf_beta`, `hm_omega`, `hm_psi`) and `lang_code="h"`. A line of about 3 to 5 s generates in about 1 to 3 s after the model is loaded; model load is the slow part, so one worker process renders a whole batch.
- Voice cloning has **not** been tested (no reference clip). It must work in the code and in tests with a stub, and the real check is manual.

## Requirements
- R1. `tts_worker.py` (in the ReelForge repo, runs inside the mlx-audio environment, imports only numpy and mlx-audio, never `reelforge`): reads a JSONL batch (`{id, text, model, voice, ref_audio, ref_text, speed, lang}` per line), loads each model once, writes one 24 kHz mono WAV per line plus its duration, and prints JSON progress lines on stdout (one per finished line, with `id`, `path`, `duration_s`, and an `error` on failure that does not stop the batch). `--selftest` renders a one-word WAV and exits 0, used by `doctor`. Model-specific arguments are mapped inside the worker, so the rest of the app only deals in the neutral fields above.
- R2. The mlx-audio adapter runs the worker as one subprocess per batch (argument list, never a shell, timeout, cancel, progress to the job), then post-processes each WAV with ffmpeg: trim silence at both ends, normalise to -16 LUFS, resample to 48 kHz. Speed 0.8 to 1.25x is applied by the adapter (worker speed argument where the model has one, ffmpeg `atempo` otherwise). `doctor` gains the check from the Technical Spec: the environment exists and `tts_worker.py --selftest` renders a WAV (blocking, as listed there).
- R3. `models.toml`: the `[models.tts]` entry becomes OmniVoice (id, revision unpinned, licence Apache-2.0, licence URL), and a new fallback entry for Kokoro with its own licence. The licence warning logic already handles non-permissive models; both of these are permissive so no warning shows. Settings gain a way to choose the fallback (a `voice_model` choice in config, default OmniVoice; Kokoro selectable) and the Status panel names the voice model in use.
- R4. Voice setup per character, saved to the library with the character: **preset** (Hindi preset voices of the chosen model, e.g. Kokoro's four; for OmniVoice a small set of named Hindi starting voices defined in the adapter), **cloned** (upload a 5 to 10 s reference clip plus its transcript, stored under the data root, type- and size-checked by content like cast uploads), and **recorded line** upload per line (bypasses TTS). Each voice stores model, voice id or reference clip, default speed and default language (`hi`). A library character reused in a new project brings the same voice. Voice design is out of scope (v1.1).
- R5. Voice board API and UI, one column per scene: generate all lines in story order as one batch job (`gen_voice_take`), progress per line, play, approve, new take (different seed), edit text and re-take, speed slider 0.8 to 1.25, pause before and after 0 to 1 s, all takes kept with exactly one active, "Play scene" and "Play all" preview that stitches active takes with their pauses (in the browser or a short ffmpeg concat). Stage `VOICES_APPROVED` when every line has an approved active take; unlocks "Continue to key frames".
- R6. Approved line duration (including pauses) is written back to the scene as its shot length with `frames = 8 * ceil((duration * 24 - 1) / 8) + 1`. Lines over the scene's duration budget are flagged with the line-fitting suggestions (speed up, shorten text via the LLM, or extend the scene), as in the Product Spec.
- R7. Staleness uses the existing `artifact_inputs` and `story_changes` machinery: changing a line's text marks only that line's voice take and that scene's shot length stale; other scenes stay fresh; nothing regenerates automatically; stale items show an amber badge and one-click "Regenerate stale items".
- R8. Everything runs on the `mock` backend in tests and CI: a mock TTS worker (`--backend mock`) produces short deterministic WAVs without any model, and the job asks the GPU lease and memory pre-flight like other heavy jobs, using a configurable memory requirement (setting `voice_mem_gb`, default 4.0, same precedence as `image_mem_gb`).

## Acceptance criteria
- AC-1: Given 5 dialogue lines rendered and one re-taken, the active take is the one used for that scene's shot length (and later the one passed to the shot job).
- AC-2: Changing a line's text marks only that line's voice take and that scene's shot length stale; the other four scenes are not stale.
- AC-3: Frame math gives `8k + 1` frames for any duration (property test), e.g. 2.9 s gives 73 frames and 3.32 s gives 81.
- AC-4: `tts_worker.py` given a JSONL batch of 3 lines (stub model) writes 3 WAVs and prints one progress JSON line each; a failing line reports an `error` and the other two still succeed; the batch runs in one process (model loaded once).
- AC-5: The adapter post-processing yields 48 kHz WAVs at about -16 LUFS with leading and trailing silence trimmed (tested with generated tones and silence through ffmpeg, no model needed).
- AC-6: `doctor` fails (blocking) when the mlx-audio environment is missing or `--selftest` fails, and passes when it works.
- AC-7: The packaged `models.toml` names OmniVoice as the TTS model and Kokoro as the fallback; selecting the fallback in settings changes the model id in the batch the adapter writes.
- AC-8: Saving an approved character to the library stores its voice; a second project that uses the character gets the same voice settings and reference clip. A clone upload rejects a non-audio file and an oversized file by content, and stores accepted files under a generated name.
- AC-9: Speed (0.8 to 1.25) and pauses (0 to 1 s) outside their ranges are rejected; inside them the duration written back to the scene includes the pauses.
- AC-10: A job started with less available memory than `voice_mem_gb` fails with a message naming `voice_mem_gb`; with enough memory it runs. Only one heavy job holds the GPU lease at a time and Ollama is unloaded first.
- AC-11: `VOICES_APPROVED` is reached only when every line has an approved active take; editing an approved line's text reopens that line only.
- AC-12: Steps for AC-1 to AC-4 complete with no outbound network connection (mock TTS).
- AC-13: Manual check on the reference Mac (human listening check, not automated): with OmniVoice, 5 real Hindi lines render with correct pronunciation; the Kokoro fallback also renders them; one cloned voice from a real 5 to 10 s Hindi reference clip is generated and judged recognisable (or recorded as not working, which is then a known limitation).

## Out of scope
- Voice design from a text description, emotion hints, English voices, other TTS models as selectable options (v1.1).
- Key frames, shots, lip-sync rendering (M5); assembly, captions, word-level timings (Phase 3).
