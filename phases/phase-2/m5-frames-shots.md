Binding inputs: `ReelForge — Requirements Document.md`, `ReelForge — Product Spec.md` (Stage 4 Key frames, Stage 5 Shots, States, Manual edit options), `ReelForge — Technical Spec.md` (milestone M5, tasks `gen_frame` and `gen_shot`, the ltx-2-mlx adapter section, Shot length and frame math, Process and memory model, spikes S1, S2 and S4 findings). Requires M1 to M4 merged (M4 gives approved voice takes and shot lengths). Out of scope here: assembly, captions, export (Phase 3).

## Spike inputs (already decided, do not re-research)
- **S1 (Draw Things):** key frames are image edits: `POST /sdapi/v1/img2img` with the approved master as `init_images[0]` and an instruction prompt keeps the character identical and changes the scene (verified at 576x1024, about 100 s per edit at 20 steps). Model and steps come from `models.toml` (Kontext, 20 steps). One call per image, no batching. A second entry in `init_images` is accepted but whether it works as a second reference is **unverified**; scenes with two characters must be handled without relying on it (see R2).
- **S2 (LTX talking shot):** `ltx-2-mlx a2v` with the key frame as `--image PATH 0 1.0` and the approved voice take as `--audio` gives good lip sync on a cartoon character. Command that worked on the reference Mac: `ltx-2-mlx a2v --prompt "<motion prompt>" --audio line.wav --image still.png 0 1.0 --model dgrauet/ltx-2.3-mlx-q4 --distilled --low-ram --width 320 --height 576 --frames 81 --frame-rate 24 --seed 1 -o out.mp4`. `--frame-rate` is mandatory; `--frames` must be 8k+1; the default `--model` is q8, so always pass the q4 id from `models.toml`. A 3.4 s draft shot took 48 s with a peak memory footprint of about 15.6 GB (VAE decode is the peak), so a shot job needs about 16 GB free. Human-like characters are untested.
- **S4 (memory):** the render ran with Draw Things open (idle) and Ollama running, with no swapping, so auto-quit of Draw Things stays off by default. Unload Ollama before a heavy job, as already built.
- ltx-2-mlx 0.18.0 lives in `~/tools/ltx-2-mlx` (its own `.venv`, Python 3.11, arm64). **Run its `.venv/bin/ltx-2-mlx` directly**, not through `uv run`: `uv run` re-resolves the environment and replaced the `.venv` once during the spike. The setting `[tools.ltx] project_path` already exists.
- The a2v `--help` shows these flags: `--prompt --output --model --seed --height --width --frames --frame-rate --low-ram --audio --audio-start --distilled --image`. The action (silent image-to-video) and extend commands exist as `generate` and `extend`; their exact flags must be read from `--help` at startup, not assumed (the Technical Spec lists `--no-audio` for `generate`, which is unconfirmed).
- Lessons from M4 that apply here: stub-only tests hid two real-model defects (a script folder shadowing an installed package, and a wrong argument name). Keep the real-backend worker or script free of module names that shadow packages it imports, and run the real tool once on the reference Mac before shipping.

## Requirements
- R1. **Key frames (`gen_frame`):** for every scene, one 9:16 frame built by an img2img edit of the approved character master (the speaker's master when the scene has a speaker, otherwise the first character mentioned), with an LLM-written, editable frame prompt (setting + action + framing + style + the character's look text verbatim). Never text alone. Framing preset per card (wide, medium, closeup) from `Scene.framing`, defaulting to closeup for dialogue scenes. Per card: generate, approve, regenerate (new seed), edit prompt, upload a replacement (checked by content and size like cast uploads), and "continue from previous" (uses the previous shot's last frame once that shot exists). All takes are kept, one active. Generate-all runs one job per frame in story order, with progress per frame.
- R2. **Scenes with two characters:** the frame is built from the speaker's master (or the first named character's) and the other character's look text goes into the prompt; the UI says that a second character is described, not copied, and offers "upload replacement". No reliance on a second `init_images` entry.
- R3. **Product placement, AI mode only:** when a scene has `product_in_shot` on and the story's `product.asset` points to an existing image under the data root, the frame job also receives that image as an input artifact and the prompt asks for the real pack to appear in the character's hands or on the table. The brand-kit screens do not exist yet, so the pack image comes from `product.asset`. Manual overlay (Mode B) is v1.1. If the asset is missing the scene shows "Product image missing" and the frame still generates without it.
- R4. **ltx adapter:** `LtxAdapter` (in `adapters/ltx.py`) runs `<ltx_path>/.venv/bin/ltx-2-mlx` as one subprocess per shot (argument list, never a shell, timeout, cancel, RSS sampling through the existing runner). At startup and in `doctor` it runs the subcommand help (`a2v --help`, `generate --help`, `extend --help`), parses the flags and **refuses to run (doctor fails, no job starts) if a required flag is missing**; this is the existing `ltx` doctor check, extended, and its key stays `ltx` (a frozen M1 test pins the check list). Model id, steps and size come from `models.toml` and settings, never hard-coded.
- R5. **Shot types:** **talking** (a2v with the key frame as `--image` and the active approved voice take as `--audio`; the video keeps the audio), **action** (silent image-to-video from the key frame with the motion prompt), and **continue** (the previous shot's last frame is the start image; uses `extend` or image-to-video from the extracted last frame, whichever `--help` supports for continuation). Type is set automatically (a scene with an approved voice take is talking; `continue_from` makes it continue; otherwise action) and can be overridden per shot. Transition shots are v1.1.
- R6. **Frames and sizes:** the frame count for a shot is the M4 write-back value (`frames = 8 * ceil((duration * 24 - 1) / 8) + 1`, so 8k+1). Quality per shot: **Draft** (320x576) or **Final** (448x768), both from settings with those defaults. No guided draft-then-final workflow (v1.1); the user can re-render a shot at Final by changing its quality.
- R7. **Motion prompts:** LLM-written, editable; talking shots get an appearance-only prompt (no motion words), action and continue shots get a motion prompt, each with the character bible line. Last frame of every finished shot is extracted with ffmpeg as an artifact (`last_frame`) for continue shots.
- R8. **Shot board (`gen_shot`):** one card per scene (key frame until rendered, then a looping inline player). Per shot: render, play, approve, re-roll (new seed, same prompt), edit motion prompt, quality, upload own clip (checked by content with ffprobe: video stream, 9:16, length limit), all takes kept with one active, compare takes. **Render all** queues every unrendered shot; the queue shows order and an estimated time per shot taken from earlier renders of the same type and size (a built-in default before any history exists), with a total ("5 shots · about N min · keep the Mac plugged in"), and lets the user reorder, pause and cancel. Trim in/out is v1.1.
- R9. **Memory and processes:** a shot is one subprocess; `shot_mem_gb` setting (default 16.0, same precedence and error style as `image_mem_gb` and `voice_mem_gb`; message names `shot_mem_gb`); frame jobs use `image_mem_gb`. RSS sampling and the memory-pressure flag from M1 apply; exit codes -9 and 137 are classified "killed, likely out of memory" and the shot card offers a smaller retry (Draft size). One heavy job holds the GPU lease at a time, and Ollama is unloaded first.
- R10. **Staleness and gates:** staleness uses `artifact_inputs` and `story_changes` as in M4: changing a scene's action marks only that scene's frame and shot stale; a new active voice take marks that scene's talking shot stale; an approved frame changed marks its shot stale. Stale items show an amber "Needs update" badge and one-click "Regenerate stale items"; nothing regenerates automatically. Stage `FRAMES_APPROVED` when every scene has an approved frame (or is "continue from previous"); `SHOTS_APPROVED` when every shot has an approved active take; each unlocks the next stage button.
- R11. **Mock backend:** everything runs on the `mock` backend in tests and CI: a mock Draw Things edit returns a deterministic PNG, a mock LTX returns a short deterministic MP4 made with ffmpeg (correct size, frame count and, for talking shots, the given audio), through the same subprocess path as the real adapter where practical.

## Acceptance criteria
- AC-1: A frame job for a scene receives the approved master image(s) as inputs, and its prompt contains the character's look text verbatim.
- AC-2: With a pack image selected and `product_in_shot` on, the frame job receives the pack image as an input; with the asset missing the frame still generates and the scene reports "Product image missing".
- AC-3: A talking shot job receives the key frame and the active approved voice take as inputs and a frame count of 8k+1 equal to the scene's written-back value; an action shot job receives no audio input.
- AC-4: Given 5 rendered shots, re-rolling one produces a new take for that shot only and leaves the other four cache entries untouched.
- AC-5: The ltx adapter fails `doctor` (not mid-render) when a required flag is missing from the parsed `--help`, and passes when all are present (tested with a fake `ltx-2-mlx` script that prints a configurable `--help`).
- AC-6: A shot job killed with exit code 137 (or -9) is classified "killed, likely out of memory" and the card offers a Draft-size retry.
- AC-7: A shot job started with less available memory than `shot_mem_gb` fails with a message naming `shot_mem_gb`; with enough memory it runs; only one heavy job holds the GPU lease and Ollama is unloaded first; `shot_mem_gb` has the same precedence and validation as `image_mem_gb`.
- AC-8: The last frame of a finished shot is extracted as an artifact, and a continue shot uses it as its start image.
- AC-9: The shot board's estimate uses recorded render times for the same shot type and size when they exist, and the built-in default otherwise; the queue can be reordered, paused and cancelled, and a cancelled running shot stops its subprocess.
- AC-10: Changing one scene's action marks only that scene's frame and shot stale; a new active voice take marks only that scene's talking shot stale; other scenes are not stale; nothing regenerates automatically.
- AC-11: `FRAMES_APPROVED` is reached only when every scene has an approved frame (or is "continue from previous"); `SHOTS_APPROVED` only when every shot has an approved active take; editing an approved frame reopens only that frame and its shot.
- AC-12: An uploaded replacement frame or clip is checked by content and size (an image or video check, not the extension) and stored under a generated name; a non-image and a non-video are rejected.
- AC-13: Steps for AC-1 to AC-4 complete on the mock backend with no outbound network connection.
- AC-14: Existing frozen M1 to M4 tests pass unchanged (no new keys on existing responses such as `GET /jobs` unless a job has a `result`; the `ltx` doctor check keeps its key).
- AC-15: Manual check on the reference Mac (human visual check, recorded in `docs/manual-checks.md`): one real key frame from a real master; one real talking shot and one real action shot at Draft size; the characters read as the same across shots. Include running the real adapter once before shipping.
